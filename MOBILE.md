# CRITERIA — Mobile Wrapper Reference

> The mobile app is a Capacitor 7 shell that wraps the web frontend. No business logic lives here — it's a WebView wrapper plus a small native plugin for OAuth.

---

## Overview

```
mobile/
├── capacitor.config.ts       # Capacitor config (reads dev.config.json for serverUrl)
├── dev.config.example.json   # Template — copy to dev.config.json
├── dev.config.json           # YOUR machine's dev URL (gitignored)
├── launcher/
│   └── index.html            # Production fallback when no serverUrl is set
├── ios/                      # Xcode project (generated by Capacitor)
├── android/                  # Android Studio project (generated)
└── package.json
```

### How dev vs prod loading works

- **Dev**: `mobile/dev.config.json` exists with a `serverUrl`. Capacitor loads that URL directly into the WebView. The Capacitor JS bridge is fully attached, native plugins (including `OAuthBridge`) work without any cross-origin caveats. This is the standard Capacitor dev pattern.
- **Prod**: no `dev.config.json` (or no `serverUrl`). Capacitor falls back to `webDir` (the launcher) which is bundled as static assets and redirects to the deployed frontend.

## Dev Workflow

### 1. One-time per machine: set your dev URL

```bash
cp mobile/dev.config.example.json mobile/dev.config.json
# Edit mobile/dev.config.json so serverUrl matches your LAN IP + port
```

When your IP changes (different network, new router DHCP lease, etc.), edit the file and re-run `npx cap sync`.

### 2. Start the frontend

```bash
pnpm --filter frontend dev --host
# → Local:    http://localhost:5173/
# → Network:  http://192.168.x.x:5173/   ← use this in dev.config.json
```

`--host` makes Vite listen on the LAN so the simulator/device can reach it. (Real devices and Android emulators need the LAN IP; iOS simulator on the same Mac can also use `http://localhost:5173`.)

### 3. Sync Capacitor (after changing `dev.config.json`, `capacitor.config.ts`, or native plugins)

```bash
cd mobile
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 npx cap sync
```

(`LANG` is required because CocoaPods misbehaves under non-UTF-8 locales.)

### 4. Open in Xcode / Android Studio

```bash
npx cap open ios
npx cap open android
```

Run from Xcode (⌘R) or Android Studio (▶) on your chosen simulator/emulator. The WebView loads your dev URL directly — no launcher screen, no URL switcher.

## Auth — how Google OAuth works on mobile

Google **refuses to render OAuth in embedded WebViews** (since 2021, for security). The standard fix is to open the OAuth flow in a system-managed in-app browser sheet.

### iOS — `ASWebAuthenticationSession` (custom Capacitor plugin)

Apple's purpose-built OAuth API. Sheet-style UI (looks like Safari but isn't), auto-dismisses on the redirect URL, returns the callback URL synchronously to the calling code. No deep-link round-trip needed.

Wired in:
- [mobile/ios/App/App/OAuthBridge.swift](mobile/ios/App/App/OAuthBridge.swift) — Capacitor plugin wrapping `ASWebAuthenticationSession`.
- [mobile/ios/App/App/MainViewController.swift](mobile/ios/App/App/MainViewController.swift) — `CAPBridgeViewController` subclass that registers the plugin in `capacitorDidLoad()`.
- [mobile/ios/App/App/Base.lproj/Main.storyboard](mobile/ios/App/App/Base.lproj/Main.storyboard) — points the root view controller at `MainViewController`.

### Android — `@capacitor/browser` (Chrome Custom Tabs) + intent-filter

`Browser.open(url)` shows a Chrome Custom Tab. Supabase redirects to `com.criteria.app://auth/callback?code=…`, which is caught by the intent-filter on `MainActivity` and dispatched to JS via `@capacitor/app`'s `appUrlOpen` event.

Wired in:
- [mobile/android/app/src/main/AndroidManifest.xml](mobile/android/app/src/main/AndroidManifest.xml) — `<intent-filter>` for the `com.criteria.app` scheme.

### JS layer (shared)

- [frontend/src/lib/supabase.ts](frontend/src/lib/supabase.ts) — Supabase client uses `flowType: 'pkce'`.
- [frontend/src/lib/native-auth.ts](frontend/src/lib/native-auth.ts) — `signInWithProviderNative()` branches on platform and either calls the iOS plugin or opens Custom Tabs on Android. `registerDeepLinkHandler()` listens for the Android callback.
- [frontend/src/App.tsx](frontend/src/App.tsx) — mounts `<NativeAuthBridge />` to listen for the Android `appUrlOpen` event.
- [frontend/src/routes/SignInPage.tsx](frontend/src/routes/SignInPage.tsx) — branches on `isNative()`.

### Required Supabase dashboard config (one-time)

In **Supabase → Auth → URL Configuration → Redirect URLs**, add:

```
com.criteria.app://auth/callback
```

Without that allowlist entry Supabase will reject the redirect with `requested url is not allowed`.

The Google OAuth client doesn't need any change — Google only sees Supabase's callback URL.

## Switching to Production

1. Deploy the frontend (Vercel or similar).
2. Either:
   - **Option A (dev-machine builds)**: delete `mobile/dev.config.json` so Capacitor stops pointing at your dev server, then update `mobile/launcher/index.html`'s `PROD_URL` constant.
   - **Option B (CI builds)**: ensure `dev.config.json` doesn't exist in CI's checkout (it's gitignored, so by default it won't), and update `mobile/launcher/index.html`'s `PROD_URL`.
3. In `mobile/launcher/index.html`, set:

   ```js
   var DEV_MODE = false
   var PROD_URL = 'https://criteria.vercel.app'
   ```

4. `npx cap sync && npx cap open ios` (or android), then build/archive as usual.

## iOS Notes

- **Capacitor**: 7.x (required for Xcode 16+/26 — Capacitor 6 will not compile).
- **Tested simulators**: iOS 17.x, iOS 18.x. Newer iOS SDKs *may* work but haven't been verified.
- **Safe areas**: handled via CSS `env(safe-area-inset-*)` — `contentInset: 'never'` in config.
- **Zoom**: disabled via `user-scalable=no` + `touch-action: manipulation`.

### First-time Xcode setup

```bash
cd mobile
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 npx cap sync
npx cap open ios
```

In Xcode: select a simulator → Run (⌘R).

## Adding Native Plugins

```bash
cd mobile
npm install @capacitor/camera        # example
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 npx cap sync
```

Plugins currently installed:
- `@capacitor/app` — receives the `appUrlOpen` deep link from Android OAuth.
- `@capacitor/browser` — opens Chrome Custom Tabs for Android OAuth.

Plus our custom inline plugin `OAuthBridge` (iOS only, ASWebAuthenticationSession).

Plugins likely needed in later phases:
- `@capacitor/camera` — property photo uploads
- `@capacitor/geolocation` — location input
- `@capacitor/push-notifications` — chat alerts
